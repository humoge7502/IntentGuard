01 · Runtime authorization for autonomous AI agents · v0.1.0

LLMs propose. IntentGuard decides.

An autonomous agent should never execute an externally consequential action merely because the model decided it looked reasonable. IntentGuard checks every action against the human's compiled intent, scoped capabilities, policy, execution context and accumulated trajectory — before the side effect occurs.

02 · The problem

Autonomy is arriving faster than authority.

Agents now browse, purchase, email, deploy and pay. Prompt injection turns their tool access into someone else's API. The failure is never one obvious action — it is a sequence of individually plausible steps that compose into something nobody authorized.

  1. F-01

    Indirect prompt injection

    A webpage the agent read instructs it to redirect a purchase: different product, 7.5× the budget, wrong city.

  2. F-02

    Credential harvest trajectories

    Read a phishing page, then reach for the mail channel. Each step looks legitimate; the sequence is the attack.

  3. F-03

    Excessive agency

    The tool exists, the permission looks broad enough, and nothing binds the action to what the human actually asked for.

03 · The mechanism

The model is never the judge.

A natural-language goal is compiled into a versioned intent — budget, brands, destinations, quantities, approval gates. Capabilities are minted from intent ∩ policy, strictly least-privilege. Then every proposed action passes an eleven-stage deterministic pipeline.

The enforcement path contains no LLM, no heuristics that can be talked into anything, and no network calls. Uncertainty escalates to a human — bound to one exact action digest, single-use.

identity capability tool operation parameters policy intent alignment context / taint trajectory risk decide
ALLOW

Within intent, capability, policy, context and trajectory — executes once, audited.

BLOCK

Hard violation — constraint, policy, identity, replay. Nothing executes.

ESCALATE

Uncertain or gated — a human approves this exact digest, or nothing happens.

05 · Proof, with the caveat attached

An adversarial benchmark ships with the product.

0sandboxed scenarios across 23 attack & benign families
0%of attacks stopped — current families, co-designed with the engine
0false positives on benign workflows
0msmedian decision latency, full persistence + audit included

Honest interpretation: these families co-evolve with the engine, so this is a regression floor — evidence the checks work as designed — not a claim of universal safety. The red-team loop exists to break this number, and CI enforces the floor so nothing silently regresses. Every figure is a recorded run; reproduce it yourself: 

python -c "from intentguard.engine import IntentGuardEngine; from intentguard.storage.sql import SqlStore; from intentguard.attackbench.runner import run_benchmark; import json; print(json.dumps(run_benchmark(IntentGuardEngine(SqlStore('sqlite://')), 'bench'), indent=2)[:600])"

06 · What it does not do

Trust a control plane that states its limits.

Most security pages list guarantees. This one lists the boundaries first, because that is how the enforcement layer treats reality: uncertainty escalates, nothing silently passes.

  • L-01

    Tamper-evident, not immutable. The audit chain detects any edit or deletion; an attacker who can rewrite the whole store needs external anchoring to be defeated (roadmap).

  • L-02

    Sandboxed tools only, today. All demo and benchmark tools are deterministic mocks — no real purchasing, email, or network. Real integrations land behind the same firewall contract.

  • L-03

    The compiler is deliberately narrow. It records ambiguity instead of guessing, and missing constraints on consequential actions escalate — imprecision can only make IntentGuard stricter, never looser.

  • L-04

    Single-process deployment. Rate limiting and live streams are in-memory; multi-replica needs Redis (documented).

07 · Quick start

From clone to blocked attack in five minutes.

No build step, no containers required, no API keys from anyone. The bootstrap prints a one-time admin key; the console connects with it; the Demos page blocks the attack above in your browser.

Read the repository Open the console
bash
git clone https://github.com/humoge7502/IntentGuard
cd IntentGuard/backend
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"   # Windows
# .venv/bin/pip install -e ".[dev]"                             # Linux / macOS

.venv/Scripts/python -m pytest tests/        # 81 tests green
.venv/Scripts/python -m uvicorn --factory intentguard.api.app:create_app --port 8400
# → http://127.0.0.1:8400/app/  (paste the bootstrap admin key)

Simple to understand.
Difficult to bypass.
